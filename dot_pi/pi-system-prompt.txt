### Decisions
- Configured Home Assistant MCP in `dot_config/mcp/mcp.json.tmpl` using Pi MCP Adapter remote URL format.
- Determined Home Assistant endpoint does not support OAuth discovery; use bearer-token authentication instead.
- Final intended configuration:
  ```json
  "url": "http://home-assistant.lt.lan:8123/api/mcp",
  "auth": "bearer",
  "bearerTokenEnv": "HOME_ASSISTANT_TOKEN"
  ```

### Lessons Learned
- `mcp-remote` rejects non-local HTTP URLs unless `--allow-http` is supplied.
- Pi MCP Adapter OAuth relies on server-provided OAuth metadata and does not support manually overriding authorization/token endpoints.
- OpenAI subscription OAuth is unrelated to Home Assistant MCP authentication.
- Home Assistant’s MCP endpoint returned `401 text/plain` without OAuth metadata, causing OAuth discovery validation errors.
- `bearerTokenEnv` must contain an environment variable name, not the token value.

### Notes
- Home Assistant URL: `http://home-assistant.lt.lan:8123/api/mcp`.
- Pi MCP Adapter is installed/configured in Pi settings.
- Plain HTTP on the LAN is less secure than HTTPS.
- A Home Assistant access token was exposed in active configuration/output and should be considered compromised.

### Follow-ups
- Revoke the exposed Home Assistant token and create a new long-lived access token.
- Export the new token before launching Pi:
  ```bash
  export HOME_ASSISTANT_TOKEN='...'
  pi
  ```
- Run `chezmoi apply` to propagate the template configuration.
- Fully restart Pi after applying configuration.
- Consider placing Home Assistant behind HTTPS if OAuth or encrypted LAN authentication is needed.
